Challenge #578

Atomic secable

Mr Performances is looking for an efficient algorithm to compute multiplication on an elliptic curve while protecting against physical attacks.

He chose an implementation of the curve addition law that follows the atomicity principle. This principle relies on a single, uniform sequence of operations to compute either point doubling or the addition of two distinct points, which provides strong protection against execution-time analysis attacks or side-channel leakage trace analysis. This protection is indeed necessary, as distinguishing the performed operation (doubling or addition) leaks information about the bits of the scalar, which is supposed to remain secret.

By adding dummy operations, it is fairly easy to obtain two identical sequences for evaluating point doubling or addition, but this would come at the cost of performance.

Mr Performances, true to his principles, uses a sequence without any loss of performance! His sequence is tailored for curves of the form y^2 = x^3 + b and contains only 9 modular multiplications. He challenges you to break his implementation for the standard curve secp192k1 (which has this form) using a fault attack. However, he has implemented countermeasures to mitigate such an attack:

- the scalar bits are read twice (and compared) before executing a sequence;
- the final coordinates (x, y) must form a valid point on the curve.

To this end, he provides his commented assembly code for computing multiplication with the generator on the curve. In this challenge, the code is executed in a virtual machine and you can specify the instructions to disrupt. There is no limit on the number of instructions to disrupt, but the fault model consists solely of assigning a random value to the operation's destination register. For example, to fault the first three instructions, enter 0 1 2 (separated by spaces) after the prompt.

The virtual machine documentation is available on this page.
